# フォールバック素材 — 障害時の差し替え

**採取日: 2026-08-21**（すべて実環境での実測）

> ⚠️ **モデルについて。** 本編の記録はセッション設定 `claude-opus-5` で採取したものです。**本番は Sonnet 5 の予定**なので、巻末に **Sonnet 5 での再測定**を付けました。値はすべて一致しましたが、**短いデモは 1.5〜2.5 倍の時間**がかかり、**失敗デモは挙動そのものが違いました**（Sonnet はデータベースに一度も触れませんでした）。必ず目を通してください。

## これは何か

**ネットワーク障害でデモが全滅する事態は現実に起こります。** 2026 年 8 月には rdfportal.org の全 SPARQL エンドポイントが不通になった実績があります。

`transcripts-ja.md`（および投影用の `fallback-ja.html`）には、講義で使う全デモの**実行記録がそのまま**入っています。プロンプト、ツール呼び出しの順序と引数、実行された SPARQL の全文、返ってきた実データ、そして回答文。

**ライブが落ちたら、これを投影してください。**

---

## 切り替えの判断

| 状況 | 判断 |
|---|---|
| デモが 60 秒返らない | リトライは**1 回まで**。2 回目は諦めてフォールバックへ |
| 全 SPARQL が落ちる | エンドポイント障害。SPARQL 系は全部フォールバック。**REST 系（M9 の TogoVar）は生きている可能性がある**ので試す価値あり |
| MIE やガイドは応答するが SPARQL だけ落ちる | 同上。外部エンドポイントの問題です |
| 参加者の多数が接続できない | M1 の時点で 60 分版に切り替える判断を。**後になるほど苦しくなります** |

> ⚠️ **聴衆の前での無音が最悪の結果です。** 迷ったら切り替えてください。

---

## 使い方

1. **開演前に `fallback-ja.html` をブラウザの別タブで開いておく。** 障害が起きてから探すのでは間に合いません。
2. 落ちたら、そのタブに切り替えて該当デモまでスクロール。
3. **「これは事前に実行した記録です」と正直に言ってください。** 隠す必要はありません。むしろ「データベースは生きているが今日は繋がらない」という状況自体が、第 7 章の再現性の話に接続できます。

**スクリーンショットは各自で撮ってください。** ここには含まれていません。

理由: 受講者が見るのは**あなたの画面**です。あなたが使うクライアント（Claude デスクトップ / Web / Claude Code）の見た目でないと、かえって混乱します。

撮っておくべきもの:

- [ ] 各デモの**ツール呼び出しログを展開した状態**（← これが最重要。M2 と M4 の失敗デモはログが見えないと成立しません）
- [ ] コネクタ追加画面（M1）
- [ ] 接続確認が成功した状態

収録された数値は **2026-08-21 時点**のものです。PDB は新規登録で、TogoVar は ClinVar リリースで、PubTator は取り込みで変わります。
