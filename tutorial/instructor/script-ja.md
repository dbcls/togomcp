**記号の読み方:**

- 🎤 = 話すこと（そのまま読める形。読み上げ推奨ではなく、要点の逐語化）
- ⌨️ = 打ち込むプロンプト（**そのままコピペ**）
- 👀 = 画面で指さすところ
- ⚠️ = 事故が起きうる箇所・言い忘れ注意

- 🔄 = フォールバック判断点

| 層 | 何をするか | 代表的なツール |

🎤 「グラウンディング層が『接地』と呼ばれるのは、『インスリン』『膵がん』のような揺れる言葉を、P01308、D010190 のような動かない識別子に固定するからです。**ここを飛ばすと、あとの工程が全部あてずっぽうになります。**」

## 3-2. MIE ファイル（4分）

🎤 「なぜ AI が、教わってもいないデータベースに正しい SPARQL を書けるのか。答えは『賢いから』ではありません。**説明書を渡しているから**です。」

👀 MIE の例（`uniprot.yaml` の examples 節）を投影

🎤 「MIE ファイルは、データベース1つにつき1つ用意された YAML の説明書です。設計目標は明快で、**LLM が初回で正しく速い SPARQL を書けるだけの情報を、過不足なく与える**こと。」

🎤 「中心にあるのは『**検証済みの実行例**』です。1つの例が3つの役割を同時に果たします。クエリ本体が**スキーマの形そのもの**、実行結果が**サンプルデータ**、そして `traps_avoided` が**このDB特有の落とし穴の警告**。同じことを3回書く代わりに、動く例1つに集約しています。」

🎤 「『SPARQL の前に必ず MIE を読め』というルールがある理由は2つ。**1つ目、存在しない述語名を書いてもエラーは出ません。ゼロ件が返ります。**そして AI は『該当なし』と報告します。検出が非常に困難です。**2つ目、書き方で実行時間が桁で変わります。**」

## 3-3. ★ 罠を目で見せる（4分）

🎤 「生命科学 RDF の失敗の多くは静かに起きます。もっともらしい表が返ってくる。ただし数字が違う。」

🎤 「1つのエンドポイントに複数のデータセットが同居していることがあります。共有されるノードに対して複数のデータセットがそれぞれ述語を宣言していると、グラフを指定しないクエリは全部を拾って、**行数が黙って膨らみます。**」

🎤 「対策は、MIE が指示するとおりグラフを固定することです。……ところが、ここに面白い問題があります。**MIE に従っていると、この罠は一度も発火しません。**最初からグラフが固定されるからです。つまり、黙って守っていると、罠があったことすら分かりません。」

🎤 「**わざと破ってみます。**」

⌨️
```
UniProt のヒトのライソゾーム内腔酵素を数えるクエリを、
FROM 句でグラフを固定した版と、固定しない版の両方で実行して、件数を比較して見せて。
COUNT(*) と COUNT(DISTINCT) の両方を出して。
```

⏱️ **実測 40秒**

⚠️⚠️ **最後の一文を絶対に落とさないこと。** これを付けないと罠が見えません。

👀 実測結果（2026-08-21）:

| 版 | `COUNT(*)` | `COUNT(DISTINCT ?protein)` |
|---|---|---|
| **FROM 固定あり** | **98** | **98** |
| **FROM 固定なし** | **196** | **98** |

⚠️⚠️ **「件数が変わります」とだけ言ってはいけません。** `COUNT(DISTINCT)` は**両方 98 で一致します**。片方だけ見せると「じゃあ FROM は要らないのでは？」という**逆の結論**を招きます。

🎤 「見てください。行数は 2 倍になりました。**でも DISTINCT のほうは、両方 98 で同じです。**」

（間）

🎤 「つまり『固定しないと答えが変わる』という単純な話ではありません。**DISTINCT を使っている限り、この例では答えが合ってしまう。**危険なのは `COUNT(*)` のほうで、そちらを使っていたら **196 という誤った数字が、エラーも警告もなく**返ってきます。」

🎤 「しかも膨張率は固定ではありません。対象によって 2 倍になったりならなかったりします。`AVG` や `SUM` を使う場合、結合を重ねる場合には、**DISTINCT では吸収しきれず答えそのものが狂います。**」

**続けて、出どころを突き止めて見せる:**

⌨️
```
その2倍の行はどのグラフから来ているの？ GRAPH ?g で調べて。
```

👀 2 つのグラフが同じ 98 件を返すのを指す

🎤 「**この調べ方自体を覚えて帰ってください。**『怪しい件数が出たら `GRAPH ?g` で供給元を数える』。そのまま実務で使えます。」

🔄 **これが失敗した場合:** 深追いしないこと。フォールバックの「4. グラフ固定あり／なしの比較」を投影するか、次の (c) に進んでください。

🎤 「もう1つ、実際に測ったものをお見せします。」

👀 スライド

```
COUNT(*)                 = 62
COUNT(DISTINCT ?protein) = 52      ← 19% の差
```

🎤 「あとで使うライソゾーム内腔酵素の集合を数えたときの実測です。1つのタンパク質が **EC 番号を複数持っていた**ために起きました。該当したのは7個で、**GBA1 は4個、ASAH1 は3個**持っています。**素朴に行数を数えていたら、『ライソゾーム内腔酵素62個』と報告するところでした。正しくは52です。**」

🎤 「**件数を報告する前に、`COUNT(*)` と `COUNT(DISTINCT)` を比べる。**差があるなら、何が重複しているのか説明できるまで報告しない。あとでもう一度出てきます。」
