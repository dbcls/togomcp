今日のゴール

3つあります

  1. 繋いで、使えるようになる
  2. なぜ動くのかを理解する ── これがないと、動かないときに手が出せません

今日いちばん時間を割くのは、うまくいく例ではなく、うまくいかない例です。

M0 — 導入

理由は3つ

1. 書ける人が少ない

能力の問題ではありません。年に数回しか書かないものを習得し続けるのは、投資として合理的ではないというだけです。

2. DB ごとに違う

UniProt では up:Protein。PDB では pdbo:datablock から辿る。1つ覚えても次で使えません。

3. 癖を知らないと書けない

どのグラフを指定するか、どの述語が速いか、どこで壊れるか。文書化されていないことが多い。

そして失敗が静かです。エラーではなく、間違った件数が返ってきます。

M3 — 下ごしらえ

RDF とは
「A の B は C」の山

   主語            述語           目的語
    │               │               │
    ▼               ▼               ▼
インスリン ──── 生物種 ─────────→  ヒト
    │
    ├──────── 長さ ─────────────→  110
    └──────── 関連疾患 ─────────→ 糖尿病

この3つ組を トリプル、真ん中を 述語と呼びます。どの述語が使えるかはデータベースごとに違う ── これがこの章の主題です。

SPARQL は、このトリプルへの問い合わせ言語。表に対する SQL にあたります。

「件数」とは、条件に合うトリプルが何本あるかということです。この章の後半で効いてきます。

M3 — 下ごしらえ

IRI とグラフ

<http://purl.uniprot.org/uniprot/P01308>          ← 主語（インスリン）
    <http://purl.uniprot.org/core/organism>       ← 述語（生物種）
        <http://purl.uniprot.org/taxonomy/9606> . ← 目的語（ヒト）

この URL の形をした名前が IRI。名前であって、リンク先ではありません。クリックして開くためではなく、同じものを世界中で同じ名前で呼ぶためにあります。

エンドポイント (sparql.uniprot.org)
 ├─ グラフ <.../uniprot>        ← UniProt 本体のトリプル
 ├─ グラフ <.../taxonomy>       ← 生物種のトリプル
 └─ グラフ <.../別データセット>   ← 同居している別のもの

FROM <グラフ名> と書くとその仕切りの中だけを見ます。書かないと全部の仕切りをまたいで探します。

「細かい話だろう」と思うかもしれません。この章の後半で、それが間違いであることを実演します。

M3 — MIE の中身

検証済みの実行例が原子単位

examples:
  - id: sequence_mass
    sparql: |
      SELECT ?sequence ?mass
      FROM <http://sparql.uniprot.org/uniprot>
      WHERE { ?protein up:sequence ?seq .
              ?seq rdf:value ?sequence ; up:mass ?mass . }
    traps_avoided:
      - union_inflation: FROM 句でグラフを固定しないと
        同居する他データセットの行を拾って件数が膨らむ
    verified: 2026-07-29

1つの例が3役を同時に果たす ── ①スキーマの形 ／ ②サンプルデータ ／ ③このDB特有の罠

M3 — なぜ先に読むのか

理由は2つ

1. 存在しない述語を書いても
エラーは出ない

ゼロ件が返ります。そして AI は「該当なし」と報告する。検出が非常に困難です。

2. 書き方で実行時間が
桁で変わる

特定の IRI 指定   ≫  FILTER(CONTAINS(...))
     速い                    遅い

実測：同じ答えを返すクエリが、片方は60秒でタイムアウト、片方は約5秒。

M3 — 静かな失敗

MIE を守ると、罠は
一度も発火しない

1つのエンドポイントに複数のデータセットが同居していると、グラフを指定しないクエリは全部を拾い、行数が黙って膨らみます。

対策は FROM <グラフ名> でグラフを固定すること。MIE がそう指示します。

つまり、黙って守っていると罠があったことすら分かりません。

→ わざと破ってみます。

M3 — わざと破った結果

行数は2倍。
しかし答えは合っている

UniProt のヒトのライソゾーム内腔酵素を数えるクエリを、 FROM 句でグラフを固定した版と、固定しない版の両方で実行して、 件数を比較して見せて。COUNT(*) と COUNT(DISTINCT) の両方を出して。
版COUNT(*)COUNT(DISTINCT ?protein)
FROM 固定あり9898
FROM 固定なし19698

最後の一文が重要です。これを付けないと、この罠は見えません。

M3 — この表の読み方

危ないのは
COUNT(*) のほう

「固定しないと答えが変わる」という話ではありません。

COUNT(DISTINCT) を使っている限り、この例では答えは合ってしまいます。両方とも 98 でした。

危ないのは COUNT(*) のほうで、196 という誤った数字が、エラーも警告もなく返ります。

さらに悪いことに、膨張率は固定ではありません。対象によって2倍になったりならなかったりします。

AVG／SUM を使う場合、あるいは再宣言された述語で結合を重ねる場合（k本で2k倍）には、DISTINCT では吸収しきれず答えそのものが狂います。

M3 — 診断のしかた

出どころを突き止める

その2倍の行はどのグラフから来ているの？ GRAPH ?g で調べて。

a up:Protein という型付けを2つのグラフが供給していました ── UniProt 自身と、同じエンドポイントに同居している別のデータセット。

この診断のしかた自体を覚えてください。「怪しい件数が出たら GRAPH ?g で供給元を数える」は、そのまま実務で使えます。

1つのタンパク質が EC 番号を複数持っていたため（該当7個。GBA1 は4個、ASAH1 は3個）。

M5 — スキル

MCP と スキルの違い

MCP ＝ 能力

何ができるか。UniProt を引ける、SPARQL を投げられる、ID を変換できる。

Skill ＝ 方法論

どういう手順でやるか。どの順で、何を検証するか。

同じ道具でも、手順書があるかないかで結果の質が変わる ── さっき見たとおりです。

今日の「良い問い」と「検証」を、毎回手で書かなくて済むようにしたもの。

M7 — 検証と再現性

  • 件数の膨張（62 対 52）
  • サンプリング偏り（1,581 対 32,597）
  • 定義の取り違え（局在 ≠ 機能）
  • 指標の誤解（共起 ≠ 因果）

もっともらしい数字として返ってきます。

M7 — 検証の4手順

論文に使う数字は
例外なくこの4つ

  1. 実行されたクエリを全文出させて保存 ── 要約させない。これが実験ノートです
  2. COUNT で裏取り ── 差があるのは異常ではない。説明できないまま報告するのが異常
  3. 元のDBで1〜2件を目視 ── 30秒。上位1件より「意外な1件」を見る
  4. 実行日とエンドポイントを記録 ── いつ問い合わせたかがない結果は再現できません

M7 — 責任

向いていない用途

網羅性が要件の解析「すべての」を保証できません
統計的推論件数は返しますが、検定の設計はあなたの仕事です
臨床判断絶対に使わないでください。ClinVar の分類は診断でも助言でもありません
一次データの生成既存のDBを引くだけ。新しい測定はしません

引用は2段構え ── TogoMCP と、実際に使ったデータベースの両方。TogoMCP は入り口であって、データの出どころではありません。

M9 — 仕込み (1)(2)

182件 → 1件

(1) 「GBA」は完全一致しません。HGNC が GBA → GBA1 に改名済み。ID の解決は自明ではない。

(2) 病原性バリアント182件に、日本人集団での頻度条件を掛けると ──

コホートアレル頻度
ToMMo（日本人 n≈54,000）0.000801
NCBN（日本人）0.000807
gnomAD exomes0.0000842

国際データベースの約10倍に濃縮。国際DBだけを見ていたら見落とす情報です。

M9 — 仕込み (3)

集計単位の罠

集計数えている単位合計182 と一致？
type（SNV 157 / 欠失 23 / 挿入 2）バリアント182✅ 一致
significanceバリアント × 条件457❌ 2.5倍
consequenceバリアント × 転写産物2,613❌ 約14倍

「病原性バリアント277個」と言えば誤りです。

しかも「病原性」で絞ったのに Uncertain significance が35件、Likely benign が1件出てきます ── フィルタはバリアント単位、内訳はバリアント×条件レコード単位だから。ツール自身が警告を返してきます。

⚠️ ClinVar の疾患名は分類として述べること。リスクの助言ではありません。

M8 — まとめ

3つだけ

  1. TogoMCP は SPARQL を投げる道具ではなく、どう投げるべきかの知識を配る仕組み。MIE ファイルが核心
  2. 失敗はエラーではなく、正しく見える数字として現れる。今日見たものは全部エラーが出ませんでした
  3. 12秒で返ってきた数字を論文に書かない。査読で聞かれたときに答えられません
